# 问答语义事件标注说明（试行）

标注对象是一个“当时可见的文本条目”，不是公司年度标签，也不是未来股价。`question` 条目只含提问文本；`reply` 条目含此前提问和后来已可见的回复。两个阶段可形成不同判断。来源时间目前是公开时间的代理，不能视为已核实的网页发布时间。

每条先选 `status`：`unlabeled` 表示未开始，`needs_review` 表示信息不足或标注分歧，`labeled` 表示完成。没有明确可抽取事件时填 `events: []` 并标为 `labeled`，不要为了凑类别填写 `other`。需要至少两位互不见对方答案的标注者独立完成，分歧经第三人或书面讨论裁定后形成单独的最终版；自动建议不能充当人工金标准。

一个事件的 `event_type` 只描述内容：`regulation` 监管/政策，`liquidity` 现金流和融资，`earnings` 经营与业绩，`governance` 治理/披露/诉讼，其他明确事件用 `other`。多个独立事件可填多个对象。同一条回复若只是“请关注公告”，通常没有可抽取的具体事件。

`direction` 是**相对于该公司经营或风险的文字含义**，不是未来收益、股票涨跌或交易建议。问题句“公司会受益吗？”通常方向为 `unknown`；仅凭提问者猜测，不得标为公司确认的利好。若回复否认提问中的事实，以回复为准，并在证据中精确引用否认文字。没有明确行业证据时 `affected_industries: []`；行业分类体系尚未确定，不猜测行业。`horizon` 只在文字说明时间范围时填 short/medium/long，否则 `unknown`。`intensity` 表示文本表达的事件强弱，`uncertainty` 表示语义或事实尚未确定的程度，均在 0～1；两个连续分数在正式实验前需增加双人一致性或分桶校准，不可从股价倒推。

每个事件至少一个 `evidence_spans`。`source` 必须是当前条目实际包含的 `question` 或 `reply`；`start` 从 0 起、`end` 不包含终点，`quote` 必须与对应文本的 Python 字符串切片完全一致。标注中不得使用财务表、用户名称、`Isviolated`、未来回复或实验测试收益来解释文本。

标注包刻意按七组字面关键词和无关键词组抽样，且每个阶段、每个公司分组保持配额。这使稀有话题得到覆盖，但不是总体发生率样本。测试公司的答案不得用于修改训练阶段的提示或规则。研究报告需同时给出有效标注数、分歧和裁定方法、解析失败率、事件检出与类别 F1；单事件方向和证据跨度分数仅在类型匹配子集上报告，不得当作总体准确率。

本地标注文件位于 Git 忽略的 `research_outputs/semantic_annotation_pilot_2020/`。`annotation_items.jsonl` 含原文与来源 ID；复制 `annotation_template.jsonl` 给独立标注者填写 `annotator_id`、`status`、`events` 和 `notes`，保留 `item_id` 与 `source_text_sha256` 原值。最终经审核的标签另存新文件，不覆盖模板或来源。模型输出必须独立记录 `model_id`、`prompt_version`、`source_text_sha256`、结构化事件和解析错误；源文本哈希不同的输出会被拒绝。

## 双人审核与裁定的实际文件流程

运行 `review_workflow prepare` 会生成 `reviewer_a_tasks.jsonl`、`reviewer_b_tasks.jsonl` 和各自的**空白**标签模板。任务文件只保留条目 ID、源文本哈希、question/reply 阶段及当时可见的文本段；结构化股票代码、训练/测试分组和抽样层被隐藏，但原文本身可能透露公司身份。两份任务顺序不同。每位审核者应单独取得自己的任务文件与标签模板副本，不看另一人的答案，也不看模型输出。复制模板到各自独立的工作文件中填写，不覆盖生成的空白原件。

完成后使用 `review_workflow compare` 对照两份工作文件。程序验证源文本哈希、证据跨度、每份文件内部的审核者身份及两人身份不同，报告双方均完成条目的事件有无一致率、Cohen κ、完整事件清单一致率，并输出逐条 `disagreements.jsonl` 与 `pending_items.jsonl`。这些统计只覆盖双方均标成 `labeled` 的条目；κ 在没有类别变异时未定义。程序无法从 ID 证明审核者确为真人或真实独立工作，这是实际审核流程的责任。

比较目录还会生成空白 `adjudication_template.jsonl`。**先复制到另一文件再填写**，保留比较目录中的原件供哈希复核。`review_workflow finalize` 只有在全部条目完成双人审核、裁定文件逐条 `labeled`、裁定者 ID 与两位审核者不同、每条分歧有书面说明时才导出 `gold_labels.jsonl`。一致条目也需裁定者显式签署，程序不会自动晋升为金标准。最后仍应由研究负责人抽查事件含义和文本证据；格式门槛不能替代人的判断。

当前 128 条仍全部未审核；空白双人模板运行的对照结果为 `no_dual_review`，没有人审准确率或金标准。
