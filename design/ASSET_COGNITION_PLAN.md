# MarketMirror 金融资产认知实施计划

更新：2026-10-05。状态：后续方向储备，暂不推进。用户明确要求先完成三类 Agent 平台，再向赛题方向扩展。以下内容不是当前开发排期，新增能力均不表示已交付。

当前优先级：完善激进型、保守型、机构型的决策解释、参数配置、对照实验、结果可视化及运行失败恢复。资产认知、本体、Nexent 与 Skills 集成暂缓；已有方案与只读资料盘点保留，不继续扩建。

## 产品目标

将问答、正式披露、财务表及政策材料关联为可检索、可核验的数据资产，通过 Nexent 的 MCP 与 Skills 执行跨文档研判；现有三类策略仿真作为下游情景实验保留。先覆盖金融，不扩展其他行业。保留已有研究结果，不以高保真行情或收益预测作为本阶段验收要求。

## 已核查基础与边界

- `design/README.md`：平台已提供文本事实提取、原文引文绑定、情景参数、配对仿真和归档。文本引文匹配不等于语义判断正确。
- `design/text_analysis.py`：可复用来源哈希、逐字引文与偏移核验机制；当前单段文本约束不适合作为所有文档的统一解析器。
- `research/ISSUER_FORMAL_DISCLOSURE_INVENTORY_2019_2020.md`：研究文档记录正式披露目录、三季报原始 PDF 与页索引，以及后续半年报材料。接入前必须逐项检查实际文件、哈希和提取结果，不将报告记录直接当作本次验收。
- `research/data_pipeline/restricted_assets_tables.py`：已有单位、数值、空白与横线状态区分，可复用其数据语义。不得将缺失值填零。
- 当前未验证统一资产目录、本体版本管理、多跳问答、Nexent 运行链路或可导入 Skill 模板；不得在界面标记为已支持。

## 第一条端到端业务闭环

问题：截至指定日期，一家公司的项目进展和财务约束有哪些已披露依据，哪些信息相互矛盾或仍然缺失？

选样依据是问答、报告和政策的真实覆盖情况，不根据生成效果挑选。先盘点文件再确定公司。无适用政策时明确返回未找到适用依据，不强行建立政策影响关系。

输入 → 文件登记与解析 → 公司/项目关联 → 按截止日期检索 → 证据补检 → 确定性数值计算 → 结论及证据链 → 可选情景实验。

## 资产与证据契约

1. 资产 ID 标识逻辑资料；版本 ID 标识一次具体内容；原始字节 SHA-256 用于完整性和去重；实体 ID 标识公司或项目。文件同名不能覆盖旧版本，字节相同也不能丢弃不同的来源记录。
2. 每个版本保存文件类型、标题、来源、获取时间、公开时间、报告期、解析器版本和解析状态。公开时间未知时不默认为报告期。
3. 证据定位区分文本偏移、PDF 页码及区域、工作表及单元格、图像区域。解析文本应关联原始版本，不能只保存模型总结。
4. 数值记录原值、币种、单位、期间、合并/母公司口径及缺失状态。程序执行换算与计算，保留输入证据和公式。
5. 图谱边区分来源明示事实、推断、待确认；每条边携带证据 ID、有效时间、提取版本与复核状态。引文验证与语义复核分别记录。

## 本体与标准

最小本体：公司、项目、行业、经营事件、指标观测、政策条款、披露文件。公司与证券代码分开建模，避免名称变化或多证券造成错误合并。

模型提出候选实体类型、关系和字段；结构检查与助手单人认真复核后发布。歧义进入待确认队列，不恢复双人复核要求。

实例更新与本体更新分开：添加某公司的报告是实例更新；引入新关系或修改字段定义是本体更新。记录版本差异、迁移结果和回滚路径。历史分析绑定旧版本，发布新版不改写旧结论。

标准映射须保存标准名称、版本、条款、适用范围和匹配类型；初期挑选一种真实相关的行业分类或披露口径完成映射。不把模型认为相似标记成标准精确匹配。

## Nexent 集成与复用

先完成集成探针，再扩建界面：选定并记录实际 Nexent 版本，通过一个 MCP 工具读取已登记证据，由一个已导入 Skill 产生可溯源结果，保存真实执行记录。

计划工具边界：资产查询、证据检索、证据原文读取、实体关系查询、数值计算、现有仿真调用。工具返回结构化 ID 和状态，避免仅返回无法追溯的自然语言。

计划三个 Skill：资料入库与关联、经营事件跨文档核验、政策适用性与情景推演。每个包包含输入输出约定、工具依赖、失败处理、版本和可执行示例。新环境导入复现后才能称为可部署模板。

## 实施顺序与验收

| 阶段 | 产物 | 完成证据 |
|---|---|---|
| 1 存量盘点与集成探针 | 实际文件清单、选定案例、Nexent 调用记录 | 本地文件及哈希核实；真实工具和 Skill 执行成功，不能以自建 HTTP 调用替代 |
| 2 统一资产入口 | 上传/登记、版本、解析、来源预览 | 文本、表格、图文各有真实样本；重复导入、解析失败和版本变化均可检查 |
| 3 本体与证据关联 | 最小本体、公司关联、标准映射 | 同名歧义保留；每条已接受关系可定位来源；一次本体变更和回滚可复现 |
| 4 检索与多跳推理 | 补检流程、计算、证据链 | 跨至少两份资料的真实问题闭环；证据不足、冲突、日期和口径错误有明确处理 |
| 5 产品界面与模板 | 资产、分析、证据、知识、工作流、实验页面 | 页面读取真实记录；错误可恢复；Skill 新环境导入与示例复现 |

建立固定问题集，覆盖单文档、跨文档、计算、时点、矛盾和不可回答问题。分别测资产解析、实体关联、证据定位、结论支持与任务成功率；不得用仿真账本测试通过率代替认知能力评估。问题集冻结后记录每次版本结果，避免只展示成功案例。
